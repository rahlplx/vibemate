## 2026-07-02 - Telemetry startSpan Bounded Eviction Bottleneck
**Learning:** Converting high-frequency Maps to arrays (`Array.from(map.values())`) and sorting them with $O(N \log N)$ complexity on every span creation is a severe bottleneck. By skipping array conversion entirely when the map size is below the bounded limit (`maxSpanCount`), and utilizing a single-pass $O(N)$ linear scan for single-span overflows (`overflow === 1`), we can reduce hot path overhead and achieve up to a ~2.4x speedup under bounded limits. Additionally, synchronizing auxiliary tracking sets (like `contentSpanIds`) on eviction prevents long-term memory leaks.
**Action:** Always check Map boundaries via `.size` before converting collection to array, and prioritize single-pass linear scans over full sorts when overflow counts are small or equal to 1.
